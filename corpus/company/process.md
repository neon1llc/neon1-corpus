# How a project runs

1. **Listen.** Show me how the work gets done today. One real example is enough.
2. **Propose.** A few options, from the quickest fix to the fuller build, each with an estimate, the effort, and what it gets you.
3. **Decide.** You pick. Sometimes that means a new system. Often it's a setting, a cleanup, or leaving it alone.
4. **Build.** Small changes, tested, and shown to you as they land.
5. **Hand over.** I show you how it works and write it down, so you can run it without me. Then I check it's doing what we agreed, and keep improving it if you want ongoing care.

Every project then runs through the same four layers in [1NEON](../products/1neon.md): Needs, Execute, Observe, Normalize. [See a sample project](https://neon1.tech/1NEON/example), start to finish, with made-up data, or [try the demo](https://neon1.tech/1NEON/demo/).
